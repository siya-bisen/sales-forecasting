# Quick Reference: Integration Guide

## For Quick Setup

### 1. No Setup Needed for Basic Usage
System works out-of-the-box without Gemini API key:
```bash
# Just run - explanations will be rule-based
python -m uvicorn backend.main:app --reload
```

### 2. Enable Gemini (Optional)
Get your Gemini API key from: https://ai.google.dev

Set environment variable before starting:
```bash
# macOS/Linux
export GEMINI_API_KEY="your-key-here"

# Windows PowerShell
$env:GEMINI_API_KEY = "your-key-here"

# Or in .env file in backend directory
GEMINI_API_KEY=your-key-here
```

Then restart the backend.

## API Request/Response Examples

### Request
```bash
curl -X POST http://localhost:8000/api/forecast \
  -H "Content-Type: application/json" \
  -d '{
    "data": [
      {"date": "2024-01-01", "sales": 100},
      {"date": "2024-01-02", "sales": 110},
      {"date": "2024-01-03", "sales": 105},
      {"date": "2024-01-04", "sales": 120},
      ...
    ],
    "horizon": 30,
    "model": "auto"
  }'
```

### Success Response (200)
```json
{
  "data_points": 28,
  "model_used": "prophet",
  "model_reason": "Strong seasonality detected; Sufficient historical data",
  "confidence_level": "medium",
  "metrics": {"mape": 8.5},
  "forecast": [
    {"date": "2024-01-31", "value": 115.5, "lower": 110.2, "upper": 120.8},
    ...
  ],
  "summary": {
    "trend": "upward",
    "seasonality": "weekly",
    "volatility": "moderate"
  },
  "explanation": "Prophet was selected because it excels at handling seasonal patterns and trends. The forecast indicates an upward trend in sales...",
  "explanation_source": "gemini",
  "notes": ["More historical data generally leads to more accurate forecasts."]
}
```

### Error Response: Too Little Data (400)
```json
{
  "detail": "At least 2 data points are required to generate a forecast."
}
```

### Error Response: Ineligible Model (400)
```json
{
  "detail": "prophet requires at least 14 data points, but only 5 were provided. Consider using Moving Average which requires only 2 data points."
}
```

## Model Requirements at a Glance

| Model | Min Points | Auto-Eligible | Manual Selectable |
|-------|-----------|---|---|
| **Moving Average** | 2 | Always | Always |
| **Prophet** | 14 | If 14+ | If 14+ |
| **SARIMA** | 30 | If 30+ | If 30+ |

## Explanation Source Meanings

| Source | Means | When It Happens |
|--------|-------|---|
| **gemini** | AI-generated by Google Gemini | GEMINI_API_KEY is set and API call succeeds |
| **rule-based** | Generated by deterministic rules | GEMINI_API_KEY not set, or Gemini API fails |

Both provide quality explanations. Rule-based is always available.

## Troubleshooting

### Q: How do I know if Gemini is being used?
**A:** Check the response JSON - look for `"explanation_source"`. If it says "gemini", Gemini was used. If "rule-based", fallback is active.

### Q: I set GEMINI_API_KEY but explanation still says "rule-based"
**A:** Could be:
1. Did you restart the backend after setting the variable?
2. Is the API key invalid? (Check Google AI Studio)
3. Is there a network issue? Check backend logs for error messages

### Q: Can I test without an API key?
**A:** Yes! System works perfectly with rule-based explanations. You don't need Gemini at all.

### Q: Why am I getting "prophet requires at least 14 data points"?
**A:** Prophet needs enough data to detect trends and patterns. Use Moving Average for fewer points (2+) or collect more data.

### Q: What's the difference between rule-based explanations?
**A:** Rule-based uses pre-written logic based on model type, volatility, trend, etc. Gemini generates natural language explanations that better explain the specific forecast. Both are useful - Gemini is more natural, rule-based is always available.
